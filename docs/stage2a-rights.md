# Stage 2A rights and public-fixture boundary

Status: **REVIEW DRAFT — NOT A RELEASE APPROVAL** (2026-10-19)

This document records a conservative provenance boundary for the unpublished
Stage 2A candidate. It does not choose a first-party license, grant permission
to redistribute third-party material, or authorize publication. A public URL
is a source reference; it is not by itself a license for copying the source
content, issue prose, attachments, data, or private execution records.

## Target public fixture

The intended public fixture is limited to a first-party driver and newly
generated numerical observations, schemas, and deterministic offline checks.
It must contain no PyTorch framework source, no verbatim Issue content or
Issue attachment/data, no private Agent trace, and no user or host paths.
The already exposed development E012 case may be labelled as a development
fixture or regression example; it is **not held-out evidence** and must not be
described as a new unseen evaluation.

The optional PyTorch dependency is an environment requirement. It is not a
copy of PyTorch source. If a release ever bundles framework source or binaries,
that is a separate third-party redistribution review and requires the exact
upstream notices and license conditions.

## Public-source observations

The source review used read-only GitHub and official license pages:

- [PyTorch Issue #199054](https://github.com/pytorch/pytorch/issues/199054),
  opened 2026-09-29 and updated 2026-10-10. Its body contains an inline Python
  reproduction, an impact description, and environment/version metadata. The
  body and the two visible comments did not expose an attachment URL.
- [PyTorch v2.9.1 LICENSE](https://github.com/pytorch/pytorch/blob/v2.9.1/LICENSE),
  API content SHA `966a609b61e537d94133d6dfbcf9d0a9a1c04e5a`. The text is a
  BSD-3-Clause-style grant with project-specific copyright notices. GitHub's
  API license detector reports `other`/`NOASSERTION`; the exact upstream text,
  not the detector label, controls any redistribution decision.
- [GitHub Terms of Service, Section D](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service),
  effective 2026-04-27. The terms distinguish ownership of user content from
  the service-scoped rights for public Issues and say that additional rights
  may be granted by adopting a license. This supports treating a public Issue
  as a citation target, not as an automatic broad downstream license for its
  prose, code, attachments, or data.
- [OSI MIT License](https://opensource.org/license/mit/),
  [OSI Apache License 2.0](https://opensource.org/license/apache-2-0/),
  [SPDX MIT](https://spdx.org/licenses/MIT.html),
  [SPDX Apache-2.0](https://spdx.org/licenses/Apache-2.0.html), and the
  corresponding SPDX license-list records. Both candidate first-party
  licenses are OSI-approved and have the stated SPDX identifiers.

The Issue is useful as a public pointer to the reported behavior. Its public
visibility does not establish a downstream license for every item embedded in
the report.

## Recommended release gates

Before any public release, the owner should separately decide and record:

1. a first-party license choice and the exact notice/metadata to activate it;
2. the final allowlisted fixture contents and the development/not-held-out
   wording; and
3. whether any Issue quotation or material paraphrase beyond a bare public URL
   is acceptable with attribution. This is a conservative rights recommendation
   for this project, not an additional user authorization invented by this
   review; a later owner decision may define a narrower citation policy.

MIT and Apache-2.0 remain comparison options only. The draft files under
`license-candidates/` are explicitly not in force. There is intentionally no
effective `LICENSE` file in this candidate.
